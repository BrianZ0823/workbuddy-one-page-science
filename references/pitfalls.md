# 注意事项 · 踩坑集（来自实战日志 2026-08-17 / 08-18）

把"一篇文章的 8 张配图"误当成"1 张合图"是常见认知错误——动手前先确认真实模板形态（单图 vs 长卷）。

## 模板学习方法（最大教训）
- 必须**下载真实参考图 → 像素采样 → 重写 spec**；再也不要"凭通用美学猜"。
- 模型不支持看图（Read 报错）时，**不要放弃**：下载原图 PNG/BMP/URL，或换多模态能力；"看不到"不能作为停止条件。
- 先确认参考图真实形态（单图 vs 长卷），再决定布局。

## 中文排版
- 纯 AI 生图中文必乱码 → 文字层必须 HTML/CSS 确定性排版（可预览、可导出 PNG）。
- 早期 `mix-blend-mode: multiply` 在浅米底上把字压淡、文字无处落脚 → 改为**实色便签 + 黑文字**。
- 真实采样：参考图底色浅米、便签饱和度 ≤30%、文字深灰（不是"彩色手账"，是低饱和便签）。
- **正文禁用幼圆（YouYuan）**：部分常用中文字形缺失（如"码""与"），浏览器会 fallback 到雅黑/Noto Sans SC，导致同一段内出现两种字体、违和感极强；统一用 Microsoft YaHei / Noto Sans SC。

## 用户偏好 / 篇幅与完整性
- **不必强行压成一页纸**：篇幅按内容定，覆盖要全，名称/安装方法/步骤等关键信息不能模糊省略。
- 每个条目卡**必须含明确操作方法**（技能市场搜「名称」/ 走 GitHub / 一键包），不能模糊。
- 术语全部替换成大白话。

## 视觉细节红线（来自逐次反馈）
- 用户**不喜欢圆圈数字** → 全部方形/文字样式。
- 字号放大、留白收紧；技术卡通字体改黑体+雅黑（幼圆弃用，部分字形缺失导致混排）。
- 便利贴改为与总结框并排 flex，避免遮挡。

## 内容合规
- 不编造事实/数字/结论；研究结论必须带来源，查不到写"未确认"。
- 法律/金融类只做辅助，不替代专业意见；自动化点击/填表需权限+人工确认。
- 飞书/群分发必须人工确认（防误发）。
